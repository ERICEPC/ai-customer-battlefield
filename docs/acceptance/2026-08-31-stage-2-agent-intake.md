# 阶段 2 验收：SenseAudio Agent 录入与人工确认

## 本阶段交付

- 非测试 API 默认通过可替换的 `FollowupDraftAgent` port 调用 SenseAudio Responses API，业务用例不依赖具体模型厂商；
- 使用 JSON Schema 约束模型输出，服务端再次严格校验，模型不能改写请求中的租户、经营对象和发生时间；
- 模型只生成待确认候选，销售可以编辑摘要、跟进方式和经营事实，勾选人工核对后才写入正式记录；
- 页面显示实际模型、Prompt 版本、运行状态、耗时和可用时的 token 用量；运行回执由服务端保存，客户端修订业务字段不能改写它；
- 正式写入后立即读回并展示“本次正式入库”的摘要、跟进方式和事实；读取失败会明确提示并允许重试；
- 上游不可用、限流、超时、鉴权失败或结构不合法时 fail closed：保留原始输入、显示安全错误，不创建草稿或正式记录；
- 模型、Prompt、Prompt 版本、超时、重试次数和 API 地址均由环境配置，不写死到业务用例；
- `deterministic` adapter 只允许显式用于本地/测试回放，生产环境拒绝启用，不能静默冒充真实 AI。

## 启动

终端 A（密钥只进入 API 进程环境，不写入仓库）：

```bash
export SENSEAUDIO_API_KEY=your_senseaudio_key
pnpm --filter @battlefield/api dev:demo
```

终端 B：

```bash
pnpm --filter @battlefield/web dev
```

打开 `http://localhost:3000/login`。不要使用 `127.0.0.1:3000`，演示 API 的允许来源默认是 `localhost:3000`。

## 手动验收：真实 SenseAudio 成功链路

1. 点击“销售1”演示账号，再点击“登录作战台”；
2. 进入“跟进工作台”，经营对象选择 `Aurora Systems`；
3. 输入：`刚给客户打完电话，预算已经确认，希望我们下周三前提交方案和实施排期。`；
4. 点击“生成跟进草稿”；
5. 页面应显示“AI 已完成结构化拆解”和“待人工确认，尚未写入正式记录”，并显示真实模型、Prompt 版本、运行状态和耗时；
6. 核对并按需要修改摘要、跟进方式和事实；可增加 `budget_status` / `预算已确认`；
7. 勾选“我已核对以上内容”，点击“确认并写入正式跟进”；
8. 页面应显示“已写入正式跟进”和“本次正式入库”，可直接看到摘要、跟进方式及经营事实。

## 手动验收：失败不伪造

1. 在未提供有效密钥或上游拒绝请求的情况下重复上述生成动作；
2. 页面应显示“AI 拆解服务暂时不可用……你的输入尚未入库”；
3. 原始输入仍保留在文本框中，页面不出现 AI 成功回执；
4. 回到“经营总览”，“待确认草稿”应仍为 `0`。

## 当前外部验收门槛

本地确定性回放已完成成功态浏览器验收，但它只验证 UI、人工确认和正式写入链路，不计作真实模型成功。当前运行进程中的 `SENSEAUDIO_API_KEY` 形态与有效 `sk-` 密钥不一致，真实最小请求已触达 SenseAudio 但返回 `401`；因此“真实模型成功生成候选”仍需在 API 进程读到有效 Secret 后复验，当前不能宣称该门槛通过。

## 本阶段边界

本阶段只关闭 Agent 自然语言录入、候选核对、正式入库回执和安全失败边界。只读原始记录台账、作战地图更新和通知推送分别作为后续可见阶段验收，不在本阶段重复计算完成度。
