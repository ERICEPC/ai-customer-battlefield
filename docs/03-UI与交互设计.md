# AI 客户作战系统 V1 UI 与交互设计

> 状态：V1 实施基线
>
> 更新日期：2026-08-31
>
> 目标：让销售完成“录入、确认、推进”，让管理者完成“看变化、找依据、促行动”，同时明确区分 AI 候选、人工确认和正式事实。

## 1. 设计方向

V1 采用“深蓝商务骨架 + 蓝白高可读工作台 + 少量金色经营强调”的企业销售系统风格。页面不追求满屏科技感，而是优先表达对象、状态、证据、责任人和下一步动作。

- 深蓝负责导航、关键判断和管理视角；
- 白色与浅灰承载高密度业务数据；
- 金色只标识经营重点、T0 和需要管理介入的内容；
- 蓝色表示进行中与主要操作；
- 黄色表示待确认，红色表示风险/失败，绿色表示已确认/完成；
- AI 生成内容始终带来源、版本和“待确认”标识，不能伪装成人工事实。

## 2. 角色与默认首页

| 角色 | 默认首页 | 首屏必须回答的问题 |
|---|---|---|
| 销售 | 今日工作台 | 今天要确认什么、推进什么、哪些客户发生变化 |
| 管理者 | 经营总览 | 哪些对象上升/下降/停滞、谁需要介入、证据是什么 |
| 管理员/运营 | 运行与配置 | 哪些配置已发布、哪些任务失败、是否存在权限或导入风险 |

同一用户拥有多个角色时可切换工作视角，但数据范围由服务端授权结果决定，前端不自行扩大范围。

## 5. 应用框架

### 5.1 桌面端

```text
┌──────────────┬──────────────────────────────────────────────┐
│ 品牌/视角切换 │ 顶栏：面包屑、全局搜索、通知、用户           │
│              ├──────────────────────────────────────────────┤
│ 主导航        │ 页面标题 + 判断说明 + 当前主要动作            │
│              │                                              │
│              │ KPI / 状态摘要                               │
│              │                                              │
│              │ 主任务区                 辅助洞察/证据区       │
│              │                                              │
│ 环境与版本    │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

- 侧栏宽 240px，可收起到 72px；
- 顶栏高 64px，页面内容最大宽度 1440px；
- 业务表格在 1280px 以上优先完整显示，在窄屏转为字段分组卡片；
- 详情和证据使用右侧抽屉，重大编辑使用独立页面，不堆叠多层弹窗。

### 5.2 移动 Web

- V1 保证 390px 起无横向溢出；
- V1 底部导航保留“今日、跟进、地图、动作、通知”；账号与权限管理优先级较低，在独立“我的”页面落地后再替换“地图”入口；
- 地图在手机上转为象限摘要 + 对象列表，不强迫用户操作缩小版散点图；
- 跟进确认改为四步：候选对象 → 事实与阶段 → 建议动作 → 最终确认；
- 主要按钮固定在底部安全区，危险操作必须二次确认。

## 6. 五条关键旅程

### 6.1 跟进录入与确认

```text
输入原始跟进
  → 生成中（保留输入，可取消）
  → 匹配经营对象/联系人/商机
  → 编辑结构化事实和阶段候选
  → 查看建议动作与影响预览
  → 确认正式写入
  → 成功回执 + 地图/对象深链
```

桌面确认页采用三块区域：

1. 左侧“来源”：原始输入、发生时间、参与人和证据；
2. 中间“候选”：对象匹配、事实、阶段、摘要和字段级修改；
3. 右侧“影响”：将新增什么、阶段是否变化、哪些建议动作仍待二次确认。

确认按钮文案为“确认跟进并写入正式记录”，不能写成含混的“保存”。建议动作不随这一步自动进入待办。

### 6.2 建议动作确认

- 待确认建议以黄色状态显示；
- 必须明确责任人、计划时间、优先级和来源才能接受；
- 接受按钮文案为“创建经营动作”；
- 拒绝、修改或过期均保留状态和原因；
- 批量接受首期不开放，避免用户忽略责任和时间。

### 6.3 作战地图下钻

```text
管理摘要 → T0 独立区 → 四象限分布 → 选择点位
  → 位置原因 → 最近变化 → 主商机 → 未完成动作 → 证据时间线
```

散点图不是装饰：键盘可选、颜色之外还有形状/标签、点位支持列表等价视图。所有分数显示数据充分度和最近计算时间。

### 6.4 管理问数

- 输入前展示受控示例：“某销售本周进展”“本周阶段下降”“逾期高优动作”；
- 结果先给口径和数据截止时间，再给摘要、重点对象、证据和数据缺口；
- 每条关键结论可跳转到对象、跟进、动作或作战状态版本；
- 无数据时明确返回“没有足够事实”，不生成合理化描述；
- 越权对象不出现在提示、结果或计数中。

### 6.5 周报审阅与发布

- 默认由个人/团队负责人审阅后发布，未来可由版本化策略切换为自动发布；
- 草稿允许编辑说明，但结构化事实项只能选择纳入/排除，不能改写来源事实；
- 发布页显示周期、截止时间、数据充分度、规则/Prompt 版本和修订说明；
- 发布后冻结，事实更正通过新版本修订。

## 7. 客户作战地图布局

```text
┌────────────────────────────────────────────────────────────┐
│ 经营判断 + 数据截止时间                  [筛选] [管理问数] │
├──────────┬──────────┬──────────┬──────────┬──────────────┤
│ 对象总数 │ T0       │ 关键变化 │ 逾期动作 │ 数据不足      │
├────────────────────────────────────────────────────────────┤
│ T0 战略对象：横向卡片，显示主商机、风险、责任人与下一步    │
├───────────────────────────────────┬────────────────────────┤
│ 关系深度 × 规模潜力散点图          │ 选中对象解释抽屉         │
│ 轴、阈值、版本、图例、列表替代视图   │ 位置原因/变化/证据/动作   │
├───────────────────────────────────┴────────────────────────┤
│ 下一步经营动作：责任人、计划时间、状态、来源、是否需介入    │
└────────────────────────────────────────────────────────────┘
```

筛选保留：负责销售、内部组织单元、经营对象类型、象限、T0、数据充分度。象限名和阈值从已发布规则读取，不写死在页面代码。

## 8. 页面状态矩阵

每个主页面必须覆盖以下状态：

| 状态 | UI 行为 |
|---|---|
| 初始/空 | 解释为什么为空，并给一个符合权限的下一步动作 |
| 加载 | 使用结构骨架，避免布局跳动；超过 2 秒显示进度说明 |
| 成功 | Toast 只确认动作，关键结果保留在页面中 |
| 校验失败 | 字段旁给可修复原因，保留用户输入 |
| 并发冲突 | 显示服务器最新版本和差异，允许重新应用修改 |
| 无权限 | 不泄露对象是否存在，给出申请权限或返回入口 |
| 外部渠道失败 | 核心业务仍显示成功，单独标记通知待重试 |
| Agent 失败 | 保留原始输入，可重试、改为人工录入或查看运行编号 |
| 数据不足 | 明确缺少哪些事实，不生成虚假分数或总结 |
| 离线/超时 | 保留未提交内容并提供重试，不重复创建记录 |

## 9. 组件规范

### 9.1 AI 确认门

包含状态、来源、候选内容、修改痕迹、影响预览、运行编号和确认人。它是深模块的 UI interface，所有 AI 写入候选复用同一交互语法。

### 9.2 证据条目

显示证据类型、发生时间、确认人、摘要、敏感级别和原对象深链。敏感内容按权限脱敏，不在列表直接展示完整原文。

### 9.3 状态标签

- 待确认：黄色；
- 进行中：蓝色；
- 已确认/完成：绿色；
- 风险/失败/逾期：红色；
- 已取消/过期/无效：灰色；
- T0/管理介入：金色。

颜色之外必须配文字或图标，满足色觉无障碍。

### 9.4 表格与列表

- 数字和金额右对齐，状态、时间和责任人可筛选；
- 默认使用游标分页，不显示不可实现的“跳到最后一页”；
- 每行只有一个主要动作，其他操作进入菜单；
- 行点击进入详情，复选框、链接和按钮必须有独立点击区域；
- 批量操作仅用于不会绕过人工判断的低风险动作。

- 中文正文：`PingFang SC` / `Microsoft YaHei` / 系统无衬线；
- 正文 14px，辅助说明 12px，模块标题 18px，页面标题 28–32px；

- 禁止大面积玻璃拟态、无意义发光、跳动缩放和用渐变掩盖数据层级。

## 11. 响应式与无障碍验收

- 390、768、1024、1440px 四档无横向溢出；
- 所有核心流程仅使用键盘可以完成；
- 焦点清晰，弹窗/抽屉正确管理焦点并支持 Escape；
- 文本与背景达到 WCAG AA 常规对比度；
- 图表具备文本摘要、数据表替代视图和非颜色编码；
- 提交中的按钮防重复点击，网络重试携带同一幂等键；
- 页面标题、状态和错误使用语义化 HTML 与实时区域。

## 12. V1 UI 验收场景

当前已交付 `/workspace` 的个人、管理观察和混合范围；页面使用结构骨架、2 秒慢加载说明、显式范围文案和有界数据缺口摘要。管理问数、周报与独立“我的”页仍按后续增量实施。

1. 销售能从自然语言输入完成跟进确认，并清楚知道哪些内容尚未成为正式事实；
2. 销售能单独确认建议动作，并看到责任、时间、来源和提醒状态；
3. 管理者能从地图点位下钻到变化依据和待推进动作；
4. 管理问数的每条关键结论能回到证据，越权数据不泄露；
5. 个人/团队周报能审阅、发布和查看不可变历史版本；
6. 外部通知失败时页面仍正确显示业务成功和待重试状态；
7. 桌面和 390px 移动 Web 均可完成跟进与动作核心流程；
8. 空、错、慢、冲突、无权、Agent 失败和数据不足状态都有可恢复路径。
